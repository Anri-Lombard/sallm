## 2026-05-22 00:10 SAST - Fair final-comparison rule reinforced

Added an explicit shared-improvement backlog to
`sallm_memory/mamba_root_cause_rescue_experiment_checklist.md` and reinforced
the rule in `sallm_memory/sallm_progress.md`.

Important comparison policy:

- Mamba rescue experiments can reveal changes that help Mamba only, LLaMA only,
  both architectures, or neither.
- If a method improves both Mamba and LLaMA, record it as a shared
  decoder-only protocol improvement and carry it forward to the later LLaMA
  rerun where compatible.
- Once the Mamba recipe is defensible, the final downstream suite must compare
  best defensible Mamba against best defensible LLaMA under matched conditions:
  same splits, prompts, metric scripts, decoding/result-selection rules, and
  clearly labelled model-specific exceptions.
- A final Mamba result should always be interpreted against both the previous
  best Mamba result and the matched LLaMA result. This separates three claims:
  Mamba improved, Mamba became competitive, and the protocol improved for both
  architectures.

Current shared-improvement backlog status:

- No confirmed shared decoder-only improvement yet.
- AfriHG beam5/length-penalty is currently Mamba-only, because the matched
  LLaMA check overgenerated and degraded relative to tracked LLaMA baselines.
- T2X placeholder/reinsertion is currently LLaMA-only/negative for Mamba.
- Mamba cache/batch-size sensitivity is currently Mamba eval hygiene rather
  than a shared protocol improvement.
