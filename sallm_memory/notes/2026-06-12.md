## Corrected xLSTM POS failure inspection

- Inspected local pulled artifact:
  `outputs/hex_results/pos_test_eval_fix_20260611_fast_retry1/xlstm_multi_pos_all_test/masakhapos_all_test/results.json`.
- Used the best corrected prompt per language (`prompt_2`) and sample-level
  outputs.
- Aggregate failure shape:
  - Tswana: token accuracy `0.3279`, strict `0.3129`, exact length `0.1362`.
    Most outputs under-generate (`394/602` shorter than gold), with average
    length difference `-5.12` tags.
  - Xhosa: token accuracy `0.3567`, strict `0.3291`, exact length `0.1897`.
    Mixed under/over-generation (`280` shorter, `211` longer, `110` exact).
  - Zulu: token accuracy `0.3904`, strict `0.3507`, exact length `0.1963`.
    Mixed under/over-generation (`264` shorter, `222` longer, `115` exact).
- Main root causes from examples:
  - Output is usually non-empty and often tuple-shaped, so the model learned
    the broad task format.
  - It frequently loses token alignment: skipped initial tokens, duplicated
    later tokens, or hallucinated/reordered words.
  - Long/proper-noun/punctuation-heavy examples sometimes collapse into
    repeated English-like fragments or invalid tags, producing near-zero scores.
  - Common label confusions are open-class and morphosyntactic boundary errors:
    `NOUN <-> VERB`, `PROPN -> NOUN`, punctuation shifts, and Tswana
    `NOUN/DET/VERB/PRON` confusion.
- Representative examples:
  - Tswana doc 22: 53 gold tags collapsed to one invalid tag after hallucinated
    fragments around `Steenhuisen`; score `0.0`.
  - Xhosa doc 32: 41 gold tags collapsed to repeated `Soul of the HIV-1`
    fragments; score `0.0`.
  - Zulu doc 110: 12 gold tags collapsed to repeated `lizo` tags and a final
    punctuation; score `0.0`.
  - Contrast: Xhosa doc 60 exactly matched a short 7-token sentence, showing the
    model can do the task when length and alignment stay simple.

## POS evaluation method decision

- The corrected free-generation POS scorer is now logically valid, but it is
  not the best final benchmark for POS because invalid generations can dominate
  the score. This is exactly what happened in the xLSTM tag-sequence repair:
  the model produced repeated lexical/subword fragments instead of a valid tag
  sequence.
- Defensible final POS evaluation should be closed-label token tagging:
  - use only MasakhaPOS `test` files;
  - keep one gold UPOS tag per input token;
  - for each token position, score the same finite UPOS label set
    (`ADJ ADP ADV AUX CCONJ DET INTJ NOUN NUM PART PRON PROPN PUNCT SCONJ SYM VERB X`);
  - select the highest-scoring label per position with the same scoring rule
    for every architecture;
  - report token accuracy as the primary metric, with exact-length/parseability
    trivially enforced by the constrained protocol;
  - keep free-generation tuple/tag-sequence metrics as diagnostic evidence, not
    as the headline POS benchmark.
- The repo already has a constrained tag-sequence diagnostic script
  (`scripts/run_constrained_tagseq_eval.py`), but it reads saved lm-eval
  `results.json` samples. For the final POS result, prefer a direct test-set
  evaluator or a wrapper that proves the samples come from MasakhaPOS `test`
  and writes architecture-comparable artifacts for xLSTM, Mamba, and LLaMA.
- Do not update the Google Sheet with POS until the same constrained
  test-split protocol has been run and verified for all compared models.
