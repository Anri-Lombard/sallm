User concern:

- Current Mamba generation results are still far behind the LLaMA/transformer
  reference on T2X and AfriHG.
- Need to rule out implementation issues before treating the gap as an
  architecture/base-pretraining limitation.
- User specifically asked why tokenizer compatibility matters if the same
  tokenizer is shared across architectures.

Clarification:

- The tokenizer is not a between-architecture mismatch in the narrow sense:
  current base configs point both LLaMA and Mamba to
  `tokenizer/sallm_bpe_tokenizer`.
- The useful tokenizer check is therefore not "did Mamba use the wrong
  tokenizer?" but "does the shared tokenizer make the target texts
  long/fragmented, and does Mamba degrade more on examples with higher target
  token burden?"
- Shared tokenizer fertility can be a task-difficulty control variable. It
  cannot, by itself, explain a Mamba-vs-LLaMA gap if both models truly use the
  same tokenizer and prompt formatting.

## Final Wave Interpretation

The bounded Mamba generation defensibility wave completed:

- Base/teacher-forced validation loss audit:
  - Mamba base is much worse than LLaMA base on the same tokenizer, same
    validation prompts, and same target token burden.
  - PPL ratios: T2X about `5.3x` worse, AfriHG Xho about `2.7x` worse, AfriHG
    Zul about `2.5x` worse.
  - This makes base-model quality/lineage a real contributor to the Mamba
    generation gap rather than a speculative explanation.
- Tokenizer compatibility:
  - The tokenizer is shared, so there is no tokenizer mismatch between
    architectures in this audit.
  - The tokenizer fertility/burden is still useful as a task-difficulty control:
    T2X target fertility is about `2.97` tokens/word; AfriHG is about
    `2.7` tokens/word.
- Decoder-only output-shape rescue:
  - T2X: no better decoder setting found. More aggressive length controls cause
    severe overgeneration/repetition and lower chrF.
  - AfriHG Xho: length-seeking beam improves validation chrF from `10.95` to
    `12.81`; sampling reaches `12.86` but with worse ROUGE-L and doubled empty
    rate. Beam5/lp1.2 is safer than sampling.
  - AfriHG Zul: beam5/lp1.2 is a clean validation improvement from `14.21` to
    `17.00` chrF and also improves ROUGE-L.
- Promotion decision:
  - Do not promote any T2X decode rescue setting to test; current official best
    remains the T2X continuation result.
  - Consider official test reruns for AfriHG Xho and Zul with beam5/lp1.2 as a
    decoder-only matched-method variant. This is still a validation-selected
    diagnostic until test reruns are done.
- Defensibility:
  - The original broad concern, "is this just an implementation issue?", is
    partly answered. We found and repaired two implementation/control issues
    before scoring: missing fallback chat template in the loss audit and Hydra
    `peft_adapter` override hygiene in decode jobs.
  - The successful artifacts now support two substantive conclusions: Mamba
    base is weaker under matched teacher-forced target likelihood, and decoder
    shape rescue helps AfriHG somewhat but does not explain T2X or close the
    full LLaMA gap.

## Continued-Pretraining Recovery Gate

Decision:
