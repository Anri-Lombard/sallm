Why This Looks Like A Scoring/Formulation Problem

SIB is evaluated as multiple-choice continuation scoring over label strings. The answer choices are not equally shaped: 

science/technology
travel
politics
sports
health
entertainment
geography

The raw likelihoods systematically favour labels like geography and sports, while long labels such as science/technology are heavily penalized. That does not prove the model understands geography better; it shows the scoring setup is leaking label-string bias into the decision.

Main finding: T2X failure is not emptiness or too-short output. The model often writes a sentence-like output, but it does not keep the source entity and value.

What T2X Needs

Another broad HPO sweep would mostly search around the same failure. The narrow test that matches the observed bug is source preservation:

  • Delexicalize: generate with placeholders such as [ENT] and [VAL], then reinsert the original strings.
  • Constrain output shape: ask for a sentence with explicit copied fields before fluency.
  • Score source preservation separately: track subject hit, value hit, and both-hit alongside chrF.

What This Says About HPO

Question Answer
Did HPO fail? No. It found real wins where tuning can help: POS, News Xho, InjonGoIntent, and some NER signal.
Did HPO fully rescue xLSTM? No. It exposed task-specific ceilings: SIB scoring/formulation, NER output noise/calibration, and T2X source preservation.
Should we run more broad HPO? Not yet. The cheapest useful work is task-specific debugging.
What should we test next? SIB balanced labels, NER output constraints, and T2X placeholder reinsertion.
