Current read: We have enough evidence to say Mamba is not globally broken. It performs strongly on corrected MasakhaNews and improves substantially on T2X/AfriHG with recipe recovery and validation-metric checkpoint selection. T2X improved again with a short continuation, but AfriHG continuation from selected checkpoints regressed, mostly by making outputs shorter. T2X and AfriHG still trail the transformer baseline by a large margin, and POS/NER are not settled because their main failure is output control.

Not-Yet-Closed Questions

Question Why it matters Minimum experiment before closure
Is Mamba's base model undertrained? T2X/AfriHG gaps may reflect worse pretraining quality, not fine-tuning or architecture. Compare base validation/perplexity by language, tokenizer fertility, and base zero/few-shot generation quality against LLaMA.
Is the gap from copy/retrieval/alignment limitations? Translation, headlines, POS, and NER all need source-conditioned copying or exact ordered outputs. Run copy/reorder/tag-copy diagnostics on both base and fine-tuned Mamba vs LLaMA.
Can POS/NER be fixed while staying decoder-only? Teacher-forced learning exists, but free generation malformed the outputs. Test constrained decoding, dynamic length control, per-token loglikelihood tagging, and matched LLaMA controls.
Can AfriHG/T2X improve with better checkpoint selection or longer training? Mamba generation metrics during training were disabled due cache issues, so eval_loss may select the wrong checkpoint. T2X also improved after a short continuation. Partly closed: checkpoint selection helped all three generation tasks and T2X continuation improved again, but AfriHG Xho/Zul continuation regressed. Further gains likely need output-length/control or base-quality diagnostics, not blind longer training.
Is Hugging Face Mamba generation a bottleneck? We saw cache/generation friction and eval OOM fallback. Run HF-vs-official mamba_ssm logits/generation parity probes on the same checkpoint and prompts.

Next Experiment Queue

  1. POS/NER output-control rescue: exact-label vocabulary constrained decoding, dynamic max-new-tokens by input token count, stop sequence hardening, and per-token decoder-only loglikelihood scoring.
  2. AfriHG generation rescue: blind continuation regressed Xho/Zul, so avoid promoting longer training unless paired with validation chrF/length checkpointing or an output-control diagnostic.
  3. Base-model adequacy audit: compare Mamba/LLaMA base losses, tokenizer fertility, and zero/few-shot raw outputs for the same languages and prompts.
  4. Implementation parity: run HF Mamba vs official Mamba kernels/logits/generation where possible.
  5. Only then: consider Mamba-2/hybrid attention-SSM/xLSTM architecture changes.
