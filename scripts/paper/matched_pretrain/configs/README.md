# Matched-pretraining configs

`<arch>_{cosine,wsd}.json` are the configs for the matched run. They are generated by `../code/make_configs.py`.

- Held-out eval runs every 100M tokens up to 1B, then every 250M tokens, plus at the end.
- A resumable checkpoint is saved every 500 steps.

## Shared hyperparameters and their sources

**Peak LR is the only per-architecture tuned value.** It is chosen by the pre-registered rule below. Everything else is identical for all four:

| Hyperparameter | Value | Source |
|---|---|---|
| Optimizer | AdamW, betas (0.9, 0.95), eps 1e-8 | GPT-3 (Brown et al. 2020) and the original MzansiLM/Mamba/xLSTM/GDN runs here |
| Weight decay | **0.1** on all >=2-D tensors (changed from 0.01 on 2026-09-26) | xLSTM paper ("a weight decay of 0.1 to all our models"); Gated DeltaNet setup; Mamba and GPT-3 |
| Gradient clip | 1.0 | GPT-3; all original runs here |
| Warmup | 4% of the 1-epoch steps (289 steps = 113.6M tokens) | MzansiLM's 2,000 / 48,400 steps |
| Schedule | WSD: constant peak, (1-sqrt) cooldown over the last 20% to 10% of peak (cosine-to-10% variant kept in `*_cosine.json`) | Hagele et al. 2024; 10% floor as in GPT-3's cosine |
| Global batch | 192 x 2,048 = 393,216 tokens | MzansiLM / Mamba-2 original global batch |
| Precision | fp32 master weights + bf16 autocast | original MzansiLM/Mamba runs |
| Loss | one shared Liger fused-linear-CE, fp32 accumulation; xLSTM keeps its soft-cap of 30 | parity-checked against plain CE |
| Data and order | matched_pretrain_v1 chunk order (seed 20260926), 1 epoch | data build manifest |
| Init seed | 20260926 | - |


## Pre-registered LR-probe decision rule (written 2026-09-26 10:05 SAST, before any probe result exists)

### Probe design
- Architectures: all four (MzansiLM, Mamba-2, xLSTM, GDN).
- Peak LR: **4e-4, 1e-3 and 3e-3** (revised 10:10 SAST, before any run started; the original grid was {2e-4, 4e-4, 8e-4}). Published 125M recipes use 6e-4 (GPT-3) to 3e-3 (xLSTM paper Table 7, for Llama/Mamba/xLSTM). If an architecture's best LR is 3e-3, 6e-3 is added for that architecture only.
- Stack: fast (`--stack fast`, xLSTM `chunkwise--triton_xl_chunk`, no compile), 2x L40S per run.
- Data (revised 10:45 SAST, before any result): the probe uses **the same data as the full runs**, `matched_pretrain_v1`. It is reformatted to train.bin with its seeded chunk order kept (sha256 fd8f1cf5…). The probe reads the first 300M tokens of that order.
  - Held-out = uctnlp/mzansi-text-deduplicated validation @08bee62 (19,940 docs). Each doc is preceded by [EOS], because the training data has no [BOS].
  - The earlier probes on the old tokenized split, run with wd 0.01, are kept only as an extra record (`runs/lrprobe_<arch>_*`).
- Global batch: 192 x 2,048.
- Warmup: 289 steps = 113,639,424 tokens. This equals the full run's warmup: 4% of the 7,221 steps in 1 epoch of matched_pretrain_v1 (E = 2,839,511,040 tokens).
- Schedule: WSD over a 300M-token budget (763 steps = 300,023,808 tokens):
  - linear warmup to step 289;
  - constant peak LR to step 610;
  - (1-sqrt) cooldown over the last 20% (153 steps) to 10% of peak.
  - Loss is therefore compared on decayed weights, as Hagele et al. 2024 recommend for WSD comparisons. Un-decayed losses favour lower LRs.
- Metric: held-out CE (nats/token, text tokens, `ALL/ce`) at 300M tokens (step 763). It uses the set1 scorer on the held-out split above.
- Training loss, grad norm and LR are logged every step.

### Decision, per architecture (revised rule, 10:10 SAST, before any result)
1. **Exclusions.** An LR is excluded if any of the following hold:
   - the run diverges or has a non-finite loss or grad norm;
   - the run has a loss spike: a training loss more than 0.5 nats above its running minimum after step 100 that does not recover within 50 steps;
   - the run does not finish.
2. **Choice.** Among the remaining LRs, pick the one with the lowest held-out `ALL/ce` at 300M tokens.
3. **Ties.** If two LRs are within 1% relative of each other, take the lower LR.
4. **Edge of the grid.** If 3e-3 wins, run 6e-3 for that architecture and apply the same rule.

This is a short-horizon probe. The best LR at 300M tokens can differ from the best at the full budget; that caveat is reported with the result.


## Addendum: fifth architecture, GDN + attention hybrid (written 2026-09-28, before any hybrid result exists)

- `hybrid_wsd.json`: the matched GDN (`gdn_wsd.json`) with softmax attention (FLA `Attention`, flash-attn 2.8.3, 8 heads x 64,
  RoPE theta 1e4) at layers 3, 7, 11, 15 and 19, the Qwen3-Next 3:1 GDN:attention layout; 22 layers (17 GDN + 5 attention)
  so the size matches GDN: 126,589,832 parameters vs 127,425,448 (-0.66%).
- Everything else is identical to the other four (data, order, batch, schedule, precision, loss, seed; fast stack).
- Runs in a separate venv (`MP_PY=/scratch/lmbanr001/venvs/sallm-hybrid/bin`): the matched venv's exact package versions plus
  flash-attn 2.8.3 (official wheel), without mamba-ssm/causal-conv1d, which only Mamba-2 uses.
- LR probe: the same pre-registered rule and grid ({4e-4, 1e-3, 3e-3}, plus 6e-3 if 3e-3 wins; lowest held-out bpb at 300M
  tokens, ties within 1% to the lower LR).
